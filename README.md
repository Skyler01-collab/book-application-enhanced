# Book Application

A **Spring Boot REST API** for managing books. It demonstrates the full **CRUD** cycle with **Spring Data JPA** and an in-memory **H2** database, organised in clean controller, service and repository layers.

Beyond the basics it includes **pagination**, **request validation**, **DTOs**, a **global exception handler** with proper HTTP status codes, **unique titles**, **mock data** on startup, and a layered **test suite** (Mockito, `@WebMvcTest`, `@DataJpaTest`).

## Features

- CRUD endpoints: `POST`, `GET`, `PUT`, `DELETE`
- **Paginated and sortable** list of books (`GET /books/v1`)
- **Bean Validation** (`@Valid`, `@NotBlank`, `@NotNull`, `@Size`) with clear, field-level error messages
- **DTOs** (Java records) so the JPA entity is never exposed directly
- **Global exception handler** (`@RestControllerAdvice`) returning one consistent JSON error format
- Correct status codes: `201 Created`, `204 No Content`, `400`, `404`, `409`
- **Unique titles**, enforced in the service (friendly `409`) and by a database constraint (safety net)
- **Mock data** (12 books) loaded into H2 on startup so you can try everything immediately
- **Tests** at every layer: unit (Mockito), web (`@WebMvcTest`), JPA (`@DataJpaTest`) and full-stack integration

## How a request flows

```
Insomnia -> BookController -> BookService -> BookRepository -> H2 database
 (JSON)     validates body     business        Spring Data JPA   (book table)
            maps DTOs          rules
                 \
                  \-- any exception --> GlobalExceptionHandler --> JSON error response
```

## Data model

| Field | Type | Rules |
|-------|------|-------|
| `id` | `Integer` | Primary key, generated by the database |
| `title` | `String` | Required, max 150 characters, **unique** (case-insensitive check) |
| `author` | `String` | Required, max 100 characters |
| `genre` | `String` | Optional, max 50 characters |

## Getting started

### Prerequisites

- JDK 17 or newer
- Maven (optional, the wrapper is included)

### Run the application

```bash
git clone https://github.com/Skyler01-collab/book-application.git
cd book-application

# Linux / macOS
./mvnw spring-boot:run

# Windows
mvnw.cmd spring-boot:run
```

You can also open the project in IntelliJ IDEA and run `BookApplication`.

The API starts on **http://localhost:8080**.

### Mock data

On startup `DataInitializer` inserts **12 books** into H2 (programming titles, fiction, history and more), so the list and pagination endpoints work immediately.

- The database is in-memory: everything is reset each time the app restarts.
- To start with an empty database, set `app.seed-data=false` in `application.properties`.
- Because titles are unique, trying to add one of the seeded titles (for example "Clean Code") returns `409 Conflict`. Use a new title when you test the create endpoint.

## API endpoints

Base path: `/books/v1`

| Method | Endpoint | Description | Success | Error responses |
|--------|----------|-------------|---------|-----------------|
| `GET` | `/books/v1` | List books (paginated, sortable) | `200 OK` | `400` invalid sort field |
| `POST` | `/books/v1/addBook` | Create a book | `201 Created` | `400` validation, `409` duplicate title |
| `GET` | `/books/v1/getBook/{name}` | Find a book by title (case-insensitive) | `200 OK` | `404` not found |
| `PUT` | `/books/v1/updateBook` | Update a book (id in the body) | `200 OK` | `400` validation, `404` not found, `409` duplicate title |
| `DELETE` | `/books/v1/deleteBook/{id}` | Delete a book by id | `204 No Content` | `400` id is not a number, `404` not found |

### Pagination and sorting

`GET /books/v1` accepts these query parameters:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `page` | `0` | Page number, starting at 0 |
| `size` | `10` | Items per page (capped at 50) |
| `sort` | `id` | `field,direction`, for example `title,asc` or `author,desc`. Allowed fields: `id`, `title`, `author`, `genre` |

Example: `GET /books/v1?page=0&size=5&sort=title,asc`

```json
{
  "content": [
    { "id": 7,  "title": "1984",          "author": "George Orwell", "genre": "Dystopian" },
    { "id": 12, "title": "Atomic Habits", "author": "James Clear",   "genre": "Self-help" }
  ],
  "page": 0,
  "size": 5,
  "totalElements": 12,
  "totalPages": 3,
  "last": false
}
```

(The example shows two items to keep it short; a full page returns 5.)

### Error format

Every error uses the same JSON shape. Validation errors add a `fieldErrors` map.

```json
{
  "timestamp": "2026-10-15T09:30:00Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "path": "/books/v1/addBook",
  "fieldErrors": {
    "title": "Title is required"
  }
}
```

## Try it with Insomnia

Every endpoint was tested with [Insomnia](https://insomnia.rest/). To reproduce:

1. Create a request collection called **Book Application**.
2. Add an environment variable for the base URL:
   ```json
   { "base_url": "http://localhost:8080/books/v1" }
   ```
3. Create the requests below. For requests with a body, set the body type to **JSON**.

### 1. List books (paginated)

`GET {{ _.base_url }}?page=0&size=5&sort=title,asc`

Response: `200 OK` with the first 5 books by title (see the example above).

### 2. Create a book

`POST {{ _.base_url }}/addBook`

```json
{
  "title": "Refactoring",
  "author": "Martin Fowler",
  "genre": "Programming"
}
```

Response: `201 Created`. The new book gets id `13`, because 12 books are loaded at startup.

```json
{
  "id": 13,
  "title": "Refactoring",
  "author": "Martin Fowler",
  "genre": "Programming"
}
```

### 3. Get a book by title

`GET {{ _.base_url }}/getBook/Refactoring`

Response: `200 OK` with the book. An unknown title returns `404 Not Found`.

### 4. Update a book

`PUT {{ _.base_url }}/updateBook`

```json
{
  "id": 13,
  "title": "Refactoring",
  "author": "Martin Fowler",
  "genre": "Software Engineering"
}
```

Response: `200 OK` with the updated book.

### 5. Delete a book

`DELETE {{ _.base_url }}/deleteBook/13`

Response: `204 No Content`. Deleting the same id again returns `404 Not Found`.

### 6. Try the error cases

| Request | Expected result |
|---------|-----------------|
| `POST /addBook` with `"title": ""` | `400` with `fieldErrors.title` |
| `POST /addBook` with title `Clean Code` (already exists) | `409 Conflict` |
| `PUT /updateBook` without an `id` | `400` with `fieldErrors.id` |
| `PUT /updateBook` with `"id": 999` | `404 Not Found` |
| `DELETE /deleteBook/abc` | `400` (id must be a number) |
| `GET /books/v1?sort=hacker,asc` | `400` (unknown sort field) |

### Prefer curl?

```bash
# list, page 0, 5 per page, sorted by title
curl "http://localhost:8080/books/v1?page=0&size=5&sort=title,asc"

# create
curl -X POST http://localhost:8080/books/v1/addBook \
  -H "Content-Type: application/json" \
  -d '{"title":"Refactoring","author":"Martin Fowler","genre":"Programming"}'

# read by title
curl http://localhost:8080/books/v1/getBook/Refactoring

# update
curl -X PUT http://localhost:8080/books/v1/updateBook \
  -H "Content-Type: application/json" \
  -d '{"id":13,"title":"Refactoring","author":"Martin Fowler","genre":"Software Engineering"}'

# delete
curl -X DELETE http://localhost:8080/books/v1/deleteBook/13
```

## JPA, Spring and design concepts used

| Concept | Where | What it does |
|---------|-------|--------------|
| `@Entity`, `@Id`, `@GeneratedValue(IDENTITY)` | `Book` | Maps the class to a table with a database-generated key |
| `@Column(unique = true, nullable = false)` | `Book.title` | Adds database-level constraints |
| `JpaRepository<Book, Integer>` | `BookRepository` | `save`, `findById`, `deleteById`, `findAll(Pageable)` with no SQL |
| Derived queries | `findByTitleIgnoreCase`, `existsByTitleIgnoreCase` | Spring builds the SQL from the method name |
| Pagination with `Pageable` | `BookController`, `BookService` | Page, size and sort come straight from query parameters |
| DTOs (records) | `Dto/` | Separate the API contract from the database model |
| Bean Validation | `BookRequest`, `BookUpdateRequest` | Rejects bad input before it reaches the service |
| `@RestControllerAdvice` | `GlobalExceptionHandler` | Maps exceptions to HTTP status codes and a consistent error body |
| `@Transactional` | `BookService` | Each operation runs in one database transaction |
| `CommandLineRunner` | `DataInitializer` | Seeds the mock data at startup |
| Constructor injection | Controller and Service | Easier to test than field injection |
